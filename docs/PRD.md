# animation-video 产品需求文档（PRD）

-   项目名称：`animation-video`
-   文档版本：V1.0
-   产品类型：Web 端 2D 动画短视频制作工具
-   当前版本目标：固定格式剧本解析、人工编辑、简单人物动画、配音、字幕、MP4
    导出

## 1. 产品定位

`animation-video` 是一个通过固定格式剧本和可视化编辑器制作 2D
段子短视频的网页工具。

用户输入剧本，程序使用确定性的规则解析场景、角色、对白和姿态，生成动画草稿。用户在网页中调整人物素材、位置、姿态、对白和时间，再生成配音、字幕和视频。

本产品不是 AI 视频生成器，也不依赖 LLM 理解剧本。

## 2. 核心原则

1.  第一版剧本解析完全由普通程序完成，不调用 LLM 或 AI。
2.  只解析剧本中明确写出的信息，不猜测未写明的情节、动作、情绪或位置。
3.  第一版每个场景最多 4 个角色。
4.  第一版人物姿态只有 `standing`（站立）和 `sitting`（坐着）。
5.  第一版人物说话通过简单嘴型图片切换实现。
6.  用户可以修改所有解析结果；程序重新解析不得静默覆盖用户成果。
7.  场景、人物位置由编辑器和场景布局决定，不由解析器猜坐标。
8.  网页预览和最终 MP4 必须使用一致的动画数据和时间计算逻辑。
9.  所有主要制作操作在网页内完成。
10. 采用渐进式开发，每阶段验收后再进入下一阶段。

## 3. 第一版范围

### 3.1 必须实现

-   项目创建、打开、保存和删除。
-   人物素材管理。
-   场景背景和静态道具管理。
-   固定语法剧本编辑器。
-   场景、角色、对白和姿态解析。
-   最多 4 个角色的限制和提示。
-   站立、坐着姿态。
-   人物在画布上的拖动和位置调整。
-   人物姿态人工修改。
-   对白编辑、插入、删除和排序。
-   时间轴基础编辑。
-   TTS 统一接口，每句对白独立生成音频。
-   简单嘴型切换。
-   字幕。
-   动画预览。
-   MP4 导出。

### 3.2 暂不实现

-   LLM、AI 剧本分析、AI 分镜和 AI 动作规划。
-   AI 视频生成。
-   复杂骨骼动画、网格变形和 IK。
-   人物跑步、跳跃、打斗等复杂动作。
-   多人同时说话。
-   复杂物理模拟。
-   3D 场景。
-   自动推断情绪或肢体动作。
-   自动推断人物坐标和移动路径。

不得为了展示技术能力而擅自加入上述功能。

## 4. 用户工作流程

1.  用户创建动画项目。
2.  用户输入符合固定语法的剧本。
3.  用户点击"解析剧本"。
4.  程序显示场景、角色、对白、姿态和错误。
5.  用户修正剧本或确认解析结果。
6.  用户点击"创建动画草稿"。
7.  程序建立场景、人物和对白事件。
8.  用户在工作台调整场景、人物素材、人物位置和姿态。
9.  用户编辑对白和时间轴。
10. 用户生成 TTS 配音。
11. 系统根据音频实际时长更新对白时间轴。
12. 用户预览动画。
13. 用户导出 MP4。

### 7.3 左侧资源面板

顶部使用三个 Tab：场景、人物、道具。

#### 场景 Tab

每个场景显示缩略图和名称。 -
点击场景：设置为当前场景，若会替换已有编辑内容，先提示。 -
双击场景：打开场景编辑。 - 场景资源缺失时显示占位图和错误状态。

#### 人物 Tab

显示项目已添加的人物。 每项显示： - 人物缩略图。 - 人物名称。 -
当前姿态。 - 添加/拖入画布操作。

人物可以拖动到画布。每个场景最多 4
个角色。添加第五个角色时显示明确提示，不得静默失败。

#### 道具 Tab

展示静态道具，例如沙发、桌子、电视、冰箱、蛋糕、杯子。 -
支持拖到画布。 - 支持位置、尺寸和图层调整。 - 第一版不实现复杂交互行为。

### 7.4 中央动画画布

画布逻辑尺寸固定为 1080 × 1920，显示时等比例缩放，禁止拉伸。

画布区域包含： - 深灰色工作区背景。 - 居中的 9:16 画布。 -
可选安全区域辅助线。 - 缩放比例和"适应窗口"操作。

交互： - 鼠标单击选中人物或道具。 - 鼠标拖动改变对象位置。 -
选中后显示边界框和选中状态。 - Delete
删除当前选中对象，删除前按需确认。 - 支持调整图层顺序。 -
支持画布缩放和平移。 - 双击人物可打开人物素材编辑页。 -
拖动时必须把屏幕坐标正确转换成画布逻辑坐标。

人物位置保存为逻辑坐标，不保存浏览器像素坐标。坐标锚点必须由素材规范定义，建议人物以脚底基准点定位。

支持： - 播放、暂停。 - 播放头拖动。 - 时间轴缩放。 - 对白事件拖动。 -

跳转到事件开始位置。

## 8. 页面三：剧本编辑和解析

### 8.1 页面布局

左右分栏： - 左侧原始剧本编辑区约占 55%。 - 右侧解析结果预览约占 45%。 -
底部错误/警告区域默认收起。

``` text
┌─────────────────────────────────────────────────────────────┐
│ 剧本编辑                                      解析剧本      │
├────────────────────────────┬────────────────────────────────┤
│ 原始剧本编辑区              │ 解析结果预览                   │
│ 行号                        │ 场景                           │
│ 语法高亮                    │ 角色列表                       │
│                             │ 对白列表                       │
│                             │ 姿态                           │
├────────────────────────────┴────────────────────────────────┤
│ 错误和警告（可展开，点击定位原始行）                         │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 左侧编辑器

建议使用 Monaco Editor。

支持： - 多行文本。 - 行号。 - 基础语法高亮。 - 复制、粘贴。 - 查找。 -
错误行标记。 - 点击错误定位。 - 保存原始剧本。

按钮： - 解析剧本。 - 保存剧本。 - 清空剧本（必须二次确认）。

用户修改剧本后，不自动覆盖已确认动画数据。必须点击"解析剧本"生成新草稿。

### 8.3 右侧解析结果

显示： - 场景名称和素材匹配状态。 - 角色名称、初始姿态、素材绑定状态。 -
每句对白的角色、文本、姿态、顺序、原始行号。

点击对白项，左侧编辑器定位到对应行。

### 8.4 解析错误区域

错误类型： - 语法错误。 - 角色未声明。 - 姿态不支持。 - 场景缺失。 -
角色数量超限。 - 对白为空。

每条错误必须显示类型、行号、说明和修复建议。点击后定位到原始剧本对应行。

### 8.5 创建动画草稿

解析无阻断错误后显示"创建动画草稿"。

点击后： 1. 创建场景实例。 2. 创建角色实例。 3.
匹配人物素材；未匹配时使用占位素材。 4.
初始化人物位置（使用场景锚点或默认布局，不由解析器猜测）。 5.
初始化姿态。 6. 创建对白事件。 7. 进入动画工作台。

如果存在素材缺失，应显示待处理事项，不得伪装成已完成绑定。

## 9. 剧本固定语法

第一版采用简单、可预测的固定语法。

### 9.1 场景声明

``` text
# 场景：客厅
```

-   以 `# 场景：` 开头。
-   冒号后必须有场景名称。
-   后续对白归属该场景，直到出现下一个场景声明。
-   第一版支持多个按顺序播放的场景。

### 9.2 角色声明

``` text
# 角色：老王、小李
```

-   支持中文逗号和英文逗号分隔。
-   名称去除首尾空格。
-   同一场景角色名称必须唯一。
-   每场景最多 4 个不同角色。
-   不允许空名称。
-   未声明角色不能自动创建。

### 9.3 对白格式

``` text
角色名（姿态）：对白内容
```

例如：

``` text
老王（坐着）：你回来了？
小李（站着）：我的蛋糕呢？
老王：我不知道啊。
```

姿态可省略。省略时沿用该角色最近一次有效姿态。角色第一次出现且没有指定姿态时，默认站立。

### 9.4 姿态映射

  剧本文字   内部值
  ---------- ------------
  站着       `standing`
  坐着       `sitting`

其他姿态一律报错，不自动猜测。

### 9.5 姿态继承

``` text
老王（坐着）：你回来了？
老王：吃饭了吗？
老王：今天怎么样？
老王（站着）：我去拿水。
老王：等一下。
```

解析为：坐、坐、坐、站、站。

姿态在对应对白事件开始时生效。

### 9.6 空行和文本规则

-   空行忽略。
-   行首、行尾空格忽略。
-   对白允许中英文和标点。
-   对白内容不得为空。
-   一行对应一条对白事件。
-   第一版不支持对白中嵌入复杂动作指令。
-   普通叙述文字不能自动转换为动作。
-   不支持多人同时说话。

## 10. 人物素材要求

### 10.1 第一版姿态

每个人物至少需要： - 站立素材。 - 坐着素材。

每种姿态需要闭嘴和说话嘴型素材。眼睛素材可以包含睁眼和闭眼状态。

建议目录：

``` text
character/
└── old_wang/
    ├── character.json
    ├── standing/
    │   ├── body.png
    │   ├── head.png
    │   ├── eyes_open.png
    │   ├── eyes_closed.png
    │   ├── mouth_closed.png
    │   ├── mouth_open_small.png
    │   └── mouth_open_large.png
    └── sitting/
        ├── body.png
        ├── head.png
        ├── eyes_open.png
        ├── eyes_closed.png
        ├── mouth_closed.png
        ├── mouth_open_small.png
        └── mouth_open_large.png
```

允许素材以完整人物图片或分层 PNG
组织，但必须通过统一素材描述文件适配运行时。

### 10.2 锚点

每种姿态必须定义统一基准锚点。推荐脚底中心或坐姿接触点。

姿态切换时： - 切换对应姿态素材。 - 保持人物逻辑位置不变。 -
根据姿态锚点校准显示位置。 - 不允许人物突然跳动。

### 10.3 嘴型

第一版至少支持： - `mouth_closed` - `mouth_open_small` -
`mouth_open_large`

说话时循环切换或根据音频振幅切换；不说话时闭嘴。嘴型变化不得影响头部和身体位置。

## 11. 场景和道具

场景由背景、静态道具、人物实例、图层和人物摆放锚点组成。

第一版道具示例： - 沙发。 - 桌子。 - 电视。 - 冰箱。 - 蛋糕。 - 杯子。

支持添加、删除、拖动、缩放和图层排序。第一版不实现复杂道具交互。

画布逻辑尺寸为 1080 ×
1920。人物位置由场景布局或用户拖动决定，不由剧本解析器决定。

## 12. 时间轴和对白

### 12.1 时间结构

建议采用：

`Project → Scene → Track → Event`

每个场景有自己的时间轴。所有内部时间使用整数帧。

### 12.2 对白事件字段

``` typescript
interface DialogueEvent {
  id: string;
  characterId: string;
  text: string;
  posture: "standing" | "sitting";
  startFrame: number;
  durationFrames: number;
  audioAssetId?: string;
}
```

### 12.3 TTS 时间更新

没有音频时允许使用估算时长创建草稿。TTS 生成后： 1. 读取音频真实时长。
2. 按项目 FPS 转换为帧数。 3. 更新对白事件时长。 4.
按既定排布策略更新后续对白。 5. 更新字幕。 6. 更新场景总时长。

必须防止音频被提前截断。用户手动调整过的时间应有保护策略，自动更新前应明确说明影响范围。

## 13. TTS 和音频

-   TTS 通过统一 Provider 接口接入。
-   每句对白独立生成音频。
-   记录音频文件路径、时长、声音、语速和生成状态。
-   支持重新生成单句音频。
-   支持试听。
-   不把某一个 TTS 厂商写死在业务逻辑中。

## 14. 视频导出

默认参数： - 1080 × 1920。 - 30 FPS。 - MP4。 - H.264。 - AAC 音频。

导出配置： - 文件名称。 - 分辨率。 - 帧率。 - 输出目录。 - 视频质量。

导出步骤： 1. 检查项目数据。 2. 检查场景和人物素材。 3. 检查对白和音频。
4. 检查时间轴。 5. 计算总帧数。 6. Remotion 渲染。 7. FFmpeg 合成音频。
8. 输出 MP4。

状态必须反映真实进度或真实阶段：准备中、渲染中、音频合成中、完成、失败。不得伪造百分比。

## 15. 标准验收剧本

``` text
# 场景：客厅

# 角色：老王、小李

老王（坐着）：你回来了？
小李（站着）：我的蛋糕呢？
老王：我不知道啊。
小李：那你嘴角的奶油是什么？
老王（站着）：这是牙膏！
```

预期： - 识别一个客厅场景。 - 识别老王、小李两个角色。 -
老王初始坐着，小李初始站着。 - 识别五句对白及其顺序。 -
第三句老王继承坐姿。 - 第五句老王切换站姿。 -
生成草稿后，用户可拖动人物、修改姿态和对白。 -
生成配音后，音频、嘴型和字幕同步。 - 可以导出完整 MP4。

## 16. 产品验收总目标

一个不需要掌握专业动画软件的用户，只需按固定格式写几句角色对白，就能在网页中完成场景、人物、站坐姿态、嘴巴动画、配音、字幕和
MP4 导出。
